## What we're building

An old age home management app, used by admins and owners of individual old age homes to replace paper record-keeping. Each old age home is its own account/tenant — an admin registers their home, and from there manages their own staff, residents, and **13 registers** of records.

Two of the registers are: donation records, and admission records.

The end users are not developers, and many won't be especially tech-savvy — the UI needs to be as simple and guided as possible. This will eventually run in production for a real government client, with real elderly residents' and staff's data in it, so treat data integrity and access control as first-class concerns, not afterthoughts. As part of your clarifying questions, please also raise anything around role-based permissions (e.g. can staff edit a register or only view it?) and audit trails (who changed what, when) — I want your recommendation before we decide whether to build that in now or later.

## Tech stack (fixed — please stick to this)

- **Backend:** Node.js
- **Frontend:** React Native — one shared codebase that runs in the browser now (for fast local testing) and compiles to native iOS/Android apps later, without a rewrite
- **Database:** MongoDB Atlas (cloud-hosted MongoDB)
- **Auth:** Firebase, with two separate sign-up/login paths — user's choice at signup:
  1. Google Sign-In
  2. Email + password, with email verification via a one-time password (OTP), plus reCAPTCHA on the signup form
- **Real-time:** Socket.io (or an equivalent you recommend) for live updates — e.g. if one staff member updates a register, others viewing it should see the change without refreshing
- **Repo layout:** two top-level folders, `/frontend` and `/backend`, kept fully separate so I can edit one without touching the other
- No Demo app or fields to be made, no demo stuff.

## Registration & auth details

When an admin registers a new old age home, capture:
- Full details about the old age home itself (name, address, capacity, etc. — use your judgement on what's needed, but ask if unsure)
- Info about the manager
- Info about the staff working there
- Info about the owner

Both auth paths (Google Sign-In and email/OTP) should lead into this same registration flow.
